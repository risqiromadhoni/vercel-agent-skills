# Tier 2: agent eval

Tier 2 asks whether the skill changes what an agent writes. For each rule, the bench seeds a project with the rule's Incorrect example, asks `claude -p` to fix it in place, and scores the edited file with a regex spec. It runs twice per rule: once with the skill installed (`with`) and once without (`without`). The difference in the applied rate is the skill's measured effect.

Tier 1 (`pnpm typecheck`, `pnpm build`) checks that the Correct examples compile. Tier 2 is separate: it spends API tokens and runs only on demand.

## Pieces

| Piece | Where | Role |
|---|---|---|
| Specs | `checks/<skill>.json` | One entry per rule: regexes that must be absent or present. Hand-written and reviewable. |
| Engine | `scripts/lib/check.mjs` | `checkRule(ruleId, skill, fw, src)` returns `{ applied, failed, reason }`. |
| Seeds | `fixtures/<fw>/seeds/<rule-id>/seed.tsx` and `prompt.md` | Generated by `gen-seeds.mjs` from the rule's first Incorrect example. |
| Seed manifest | `fixtures/<fw>/seeds.manifest.json` | `{ "<id>": { status: "auto" \| "adapted", sourceHash } }`. |
| Runner | `scripts/run-eval.mjs` | Runs the agent and scores each run. Writes `results/<fw>/<skill>/<ts>.json`. |
| Report | `scripts/report.mjs` | Writes a markdown scorecard next to the JSON. |
| Gate | `scripts/selftest-checks.mjs` | Checks every spec against the rule files' own examples. |

## Commands

Run from `packages/skill-bench`.

```bash
pnpm selftest                                              # spec quality gate (no API calls)
pnpm gen-seeds --skill=react-best-practices --fw=nextjs --rule=rerender-memo --dry-run
pnpm gen-seeds --skill=react-best-practices --fw=nextjs    # writes missing seeds only
BENCH_FW=nextjs BENCH_SKILL=react-best-practices BENCH_RULES=rerender-memo BENCH_ARMS=with \
  BENCH_MODEL=claude-haiku-5-5 pnpm eval                   # one agent call
pnpm report                                                # newest results JSON -> .md
pnpm report --input results/nextjs/react-best-practices/<ts>.json
```

`pnpm eval` prints status on stderr and the path of the results JSON on stdout.

### Environment (`pnpm eval`)

| Variable | Default | Meaning |
|---|---|---|
| `BENCH_FW` | required | `nextjs` or `tanstack-start` |
| `BENCH_SKILL` | required | `react-best-practices` or `composition-patterns` |
| `BENCH_RULES` | all non-N/A rules | comma-separated rule ids |
| `BENCH_ARMS` | `with,without` | either or both arms |
| `BENCH_MODEL` | `claude-sonnet-5-5` | passed to `claude --model` |
| `BENCH_CONCURRENCY` | `2` | parallel agent runs |
| `BENCH_TIMEOUT_MS` | `600000` | per agent run; the process is killed after this |
| `BENCH_MAX_TURNS` | `30` | passed as `--max-turns` only when `claude --help` lists it (it did not in CLI 2.1.318) |
| `BENCH_BUILD` | off | `1` also runs `pnpm build` in each edited copy |

### Preflight

`run-eval.mjs` runs `claude --version`, then parses `claude --help` for `--max-turns`, `--setting-sources`, `--strict-mcp-config`, `--permission-mode`, `--allowedTools` and `--output-format`. It passes only the flags the local CLI lists. If `claude` is not on PATH, it writes `results/manual/<fw>/<skill>/index.json` plus a `prompt.md` and `seed.tsx` per rule, then exits 0.

## What one run does

1. Copies the fixture to a fresh `mkdtemp` directory. It excludes `node_modules`, `.next`, `dist`, `.output`, `.nitro`, `.tanstack`, `seeds/`, the manifests and the README. `node_modules` is a symlink to the fixture's install.
2. Removes the answer key from the copy. `src/rules/*` (the Correct stubs) and `app/rules/` are dropped, `src/rules/index.ts` is replaced with an empty map, and only `src/routes/rules/index.tsx` is kept. Without this, the agent could copy the Correct code.
3. Copies the seed to `src/seed/seed.tsx`.
4. `with` arm only: copies `SKILL.md`, `rules/`, `AGENTS.md` and `metadata.json` to `.claude/skills/<skill>/` in the copy.
5. Runs `claude -p <prompt.md> --model … --allowedTools "Read,Edit,Write,Bash(pnpm typecheck*)" --permission-mode acceptEdits --output-format json --setting-sources project --strict-mcp-config` with the copy as cwd. Project-only settings keep the user's global skills out of the `without` arm.
6. Runs `pnpm typecheck` in the copy, and `pnpm build` when `BENCH_BUILD=1`.
7. Reads the edited `src/seed/seed.tsx` back and calls `checkRule`. If the file was deleted or moved, the run scores as not applied.
8. Deletes the copy, even on SIGINT or SIGTERM.

Each rule's JSON entry has `status` (`scored`, `manual`, `na`, or `no-seed`), `mappingStatus`, and per arm `{ applied, failed, typecheck, build, costUsd, durationMs, turns, agent, seedAfter }`. `typecheckTail` appears when typecheck fails.

## Spec format

`checks/<skill>.json` maps each rule id to:

The real `rerender-memo` entry in `checks/react-best-practices.json` (no `flags` or `overrides`, so the defaults apply):

```json
"rerender-memo": {
  "mustNotMatch": [
    "useMemo\\(\\s*\\(\\)\\s*=>\\s*\\{[^}]*?return\\s*<"
  ],
  "mustMatch": [
    "\\bmemo\\("
  ],
  "notes": "Incorrect memoizes a JSX element with useMemo inside the parent. Correct extracts a memo()-wrapped child component."
}
```

An override for one framework, shown for illustration (no spec uses one yet):

```json
"overrides": { "tanstack-start": { "mustMatch": ["\\bcreateServerFn\\("] } }
```

- `applied` is true when no `mustNotMatch` regex matches and every `mustMatch` regex matches. `failed` lists the patterns that did not hold.
- Regexes are JavaScript strings, so backslashes are doubled. `flags` defaults to `ms`.
- Source is comment-stripped first (TypeScript scanner), so a commented-out anti-pattern does not count. String and template literals are kept.
- `overrides[fw]` replaces the base list for that key on that framework. It does not extend it.
- `"manual": true` means no regex can express the fix. The engine returns `applied: null`, the run is not paid for, and the report lists it under "Needs manual review". `notes` is required on every spec and should say why.
- A rule with no regex is an error. Every non-manual spec needs at least one `mustMatch` or `mustNotMatch`.

## Adding or adjusting a spec

1. Read the rule's Incorrect and Correct examples in `skills/<skill>/rules/<id>.md`.
2. Write `mustNotMatch` for the anti-pattern's API names and `mustMatch` for the fix's API names. Prefer named APIs (`useSWR(`, `Promise.all(`) over layout guesses.
3. Run `pnpm selftest`. It must report 0 mismatches. The Incorrect example has to fail and the Correct example has to pass.
4. If the rule has no labelled Incorrect or Correct example, the selftest cannot test the spec. Mark it `manual` and fix the labels in the rule file.
5. For a framework-specific fix, add an override. The selftest only checks TanStack overrides against `fixtures/tanstack-start/src/rules/<id>.tsx` when that Tier 1 port exists. Otherwise it reports the override as untested.

## Seeds

`gen-seeds.mjs` writes `seeds/<id>/seed.tsx` from the first example whose label is `Incorrect`, `Wrong` or `Bad` (whole word). The seed starts with the same `// SOURCE:` and `// HASH:` header as the Tier 1 stubs. It also writes `prompt.md` with the task text, and records `{ status: "auto", sourceHash }`.

It never overwrites an existing `seed.tsx` or `prompt.md`, nor an `adapted` manifest entry. Rules whose mapping is `na` for the framework are skipped. A seed is raw rule text, so it may reference undefined names or lack imports. In that case typecheck fails before the agent starts. Port workers should adapt the seed, then set its manifest status to `adapted`.

## Cost and runtime

- Measured: one `with` run of `rerender-memo` on `claude-haiku-5-5` cost $0.0061 and took 8 turns (smoke test). Other models and rules were not measured.
- A full run is rules × arms agent calls, so 73 × 2 = 146 for react-best-practices on one framework. Multiply by the measured per-run cost for your model before starting it. Start with `BENCH_RULES` and `BENCH_ARMS=with`.
- The default `BENCH_CONCURRENCY=2` limits parallel agent runs. Each run also runs `pnpm typecheck` after the agent finishes.
- Tier 2 is a manual or `workflow_dispatch` job. It should not run on every push.

## Limitations

- The regexes are heuristics. A correct fix written another way can fail (false negative), and a name-based regex can pass when the agent renames the thing it names (false positive). A failure is a lead for reading `seedAfter`, not a verdict. The smoke test shows this: Haiku moved the `useMemo` onto the id and skipped `memo()`, so `applied` was false even though the output is arguably a valid fix.
- The `without` arm is not fully isolated. `--setting-sources project` is meant to keep user settings and skills out, but this has not been verified for user-level `CLAUDE.md` memory, and the agent can still read absolute paths. Check `resultExcerpt` when a result looks odd.
- The answer-key removal covers the fixture copy only. The agent's `Read` tool can still open any path it knows.
- `--max-turns` is not in CLI 2.1.318, so the turn cap is only the timeout.
- Seeds from raw examples may not compile. The baseline typecheck can fail before the agent acts. Compare with the adapted seed before reading a low typecheck rate as an agent failure.
